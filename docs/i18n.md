# Guida all'Internazionalizzazione (i18n)

> **Documentazione tecnica per sviluppatori e agenti AI.**  
> Spiega l'architettura, le convenzioni e le istruzioni pratiche per mantenere e aggiungere contenuti bilingui (**Italiano** e **Inglese**) nel portfolio.

---

## 1. Architettura e Principi di Base

- **Stack**: SvelteKit 2 + **Svelte 5 Runes** (`$state`, `$derived`, `$effect`) + Tailwind CSS v4.
- **Deploy**: Static Site Generation (SSG) tramite `@sveltejs/adapter-static` con `prerender = true`.
- **Nessuna duplicazione di route**: Non utilizziamo sottocartelle di routing come `/it` o `/en`. L'intera applicazione è prerenderizzata staticamente e la lingua viene gestita in modo reattivo a livello client senza flash o ricaricamenti di pagina.
- **Persistenza & Rilevamento**:
  - Salva la scelta dell'utente in `localStorage.getItem('locale')`.
  - Se non presente, rileva la lingua del browser (`navigator.language.startsWith('it') ? 'it' : 'en'`).
  - Sincronizza l'attributo `<html lang="...">` nel DOM (anche prima dell'idratazione in `src/app.html`).

## 2. Regola Fondamentale: Cosa Tradurre e Cosa NON Tradurre

Per mantenere coerenza estetica e standard internazionali di software engineering:

### ❌ NON TRADURRE (Devono rimanere SEMPRE in Inglese):
1. **Navigazione & Branding**:
   - Voci di navigazione in `Header.svelte` e `Footer.svelte`: `About`, `Experience`, `Projects`, `Contact`.
   - Titolo/Hero principale: `"Hello, I'm Christian Ferrario Software Engineer"`.
   - Heading di contatto: `"Get in Touch"`, `"Contact Me"`.
   - Badge di sezione e metadati: `"Case Study"`, `"Tech Stack"`, e tutti i badge delle tecnologie (`Java`, `C++`, `Python`, `SvelteKit`, `Docker`, ecc.).
2. **Nomi e Titoli di Progetto**:
   - I titoli rimangono invariati (es. `Sportrack`, `Sudoku Solver`, `Sparse Iterative Solvers`, `DCT Image Compressor`, `TimeTrack`, ecc.).
3. **Call-To-Action (Bottoni)**:
   - `"View Case Study"`, `"GitHub"`, `"GitHub Repository"`, `"Live Demo"`, `"Download Report"`, `"View Source (GitHub)"`.
4. **Contatti**:
   - Email, link LinkedIn, link CV.

###  DA INTERNAZIONALIZZARE (Italiano / Inglese):
1. **Case Study dettagliati delle Dialog (`src/lib/content/projects/*.svelte`)**:
   - Testi lunghi, architettura, analisi algoritmica, metriche e scelte tecniche.
2. **Descrizioni sintetiche dei progetti (`src/lib/data/projects.ts`)**:
   - Il campo `description` e l'eventuale `highlight`.
3. **Sezioni discorsive biografiche o tecniche (`About.svelte`, `Experience.svelte`)**:
   - Paragrafi narrativi, percorsi accademici (Bicocca), dilemmi architetturali e descrizioni dei domini.
4. **Testi introduttivi e label di filtri** (es. introduzione di `MinorProjects.svelte`, Redesign Lab).

## 3. Il Modulo Core: `src/lib/i18n/locale.svelte.ts`

Il file `src/lib/i18n/locale.svelte.ts` esporta:

- **`type Locale = 'it' | 'en'`**
- **`type Localized<T = string> = { it: T; en: T }`**: Interfaccia generica per campi bilingui.
- **`getLocale(): Locale`**: Restituisce il valore corrente reattivo (`$state`).
- **`setLocale(locale: Locale): void`**: Aggiorna lo stato, memorizza in `localStorage` e sincronizza `document.documentElement.lang`.
- **`toggleLocale(): Locale`**: Inverte tra `'it'` ed `'en'`.
- **`t<T>(val: Localized<T> | T): T`**: Helper universale. Se riceve un oggetto `{ it: '...', en: '...' }`, restituisce dinamicamente la versione della lingua attiva; se riceve un valore primitivo lo restituisce invariato.

## 4. Guida Pratica: Come Aggiungere Nuovi Contenuti

### Caso A: Aggiungere o Modificare un Progetto in `src/lib/data/projects.ts`
Nei dati del progetto, definire `description` (e facoltativamente `highlight`) come oggetto `{ it: '...', en: '...' }`:

```typescript
import type { Localized } from '$lib/i18n/locale.svelte';

export const projects: Project[] = [
  {
    slug: 'nuovo-progetto',
    title: 'Nuovo Progetto', // Titolo invariato
    imageLight: '/assets/projects/nuovo/cover.jpg',
    imageDark: '/assets/projects/nuovo/cover.jpg',
    github: 'https://github.com/FerrarioChristian/...',
    demo: 'https://...',
    technologies: ['Rust', 'WebAssembly'],
    description: {
      it: 'Descrizione sintetica ma precisa in italiano con contesto tecnico...',
      en: 'Concise, high-level engineering summary in technical English...'
    },
    highlight: {
      it: 'Prestazioni Real-Time in WebAssembly',
      en: 'Real-Time WebAssembly Performance'
    },
    isFeatured: true
  }
];
```

Nel template del componente viene renderizzato semplicemente usando l'helper `t()`:
```svelte
<p>{t(project.description)}</p>
```

---

### Caso B: Creare il Case Study per la Modale del Progetto
Per ogni progetto con slug `slug-del-progetto`, creare la seguente struttura in `src/lib/content/projects/`:

1. **`src/lib/content/projects/it/slug-del-progetto.svelte`**:
   Contenuto dettagliato in italiano (sezioni, architettura, immagini, diagrammi).
2. **`src/lib/content/projects/en/slug-del-progetto.svelte`**:
   Stessa struttura con traduzione tecnica in inglese (academic / software engineering tone).
3. **`src/lib/content/projects/slug-del-progetto.svelte`** (Wrapper radice obbligatorio):
   ```svelte
   <script lang="ts">
     import { getLocale } from '$lib/i18n/locale.svelte';
     import ItContent from './it/slug-del-progetto.svelte';
     import EnContent from './en/slug-del-progetto.svelte';

     let locale = $derived(getLocale());
   </script>

   {#if locale === 'en'}
     <EnContent />
   {:else}
     <ItContent />
   {/if}
   ```

> **Come viene caricato da `ProjectModal.svelte`**:  
> Il componente `ProjectModal` carica dinamicamente il file corrispondente alla lingua corrente con fallback automatico:
> ```typescript
> import(`../content/projects/${locale}/${project.slug}.svelte`)
>   .catch(() => import(`../content/projects/it/${project.slug}.svelte`))
>   .catch(() => import(`../content/projects/${project.slug}.svelte`))
> ```

### Caso C: Testi Bilingui nei Componenti `.svelte` (About, Experience, ecc.)
Per stringhe o sezioni discorsive all'interno di normali componenti Svelte:

```svelte
<script lang="ts">
  import { getLocale } from '$lib/i18n/locale.svelte';

  // Svelte 5 Rune reattivo al cambio di lingua
  let locale = $derived(getLocale());
</script>

<!-- Frasi singole o titoli -->
<h2>{locale === 'it' ? 'Il Mio Percorso' : 'My Journey'}</h2>

<!-- Interi blocchi di testo o paragrafi -->
{#if locale === 'it'}
  <p>Testo articolato in italiano...</p>
{:else}
  <p>Detailed technical description in English...</p>
{/if}
```

Se hai liste o array reattivi nei componenti:
```svelte
<script lang="ts">
  import { getLocale } from '$lib/i18n/locale.svelte';

  let locale = $derived(getLocale());

  const items = $derived(locale === 'it' ? [
    { title: 'Titolo IT', desc: 'Descrizione IT' }
  ] : [
    { title: 'Title EN', desc: 'Description EN' }
  ]);
</script>
```

Prima di committare nuovi contenuti localizzati, verificare sempre:
- [ ] Titoli, CTA e voci di menu sono rimasti in inglese.

- [ ] `npm run check` non restituisce errori di tipo TypeScript.
- [ ] `npm run build` completa il prerendering statico con successo.
